## 1. O-2: производительность SurfaceYAt (следующий шаг)

Проблема: генерация радиуса 12 чанков ≈ 220–310 с. `UDensityFieldSampler::SurfaceYAt`
(`DensityFieldSampler.cpp:334-364`) на каждую колонку делает **линейный скан
вниз от `DensityScanTop` до `MinHeight`** (до ~383 уровней) с полным FBM3D
(`Params.octaves`) на каждом уровне; кроме того `RouteAt(x,z)` (климатический
FBM + domain warp) пересчитывается при каждом вызове, а вызовов на колонку
несколько (terrain fill, features, carvers, spawn-подбор).

Шаги (каждый — отдельный коммит с измерением):

1. **O-2.1 Базлайн.** Замер времени на колонку: микро-харнесс (тест-таргет
   `worldgen_surface_perf_probe` или env-гейт в populate-тайминге, который уже
   пишет `sample_ms/terrain_ms` в `ChunkPopulateTiming`) на seeds 777001–777003,
   radius 12. Зафиксировать в аудите числа до правок.
2. **O-2.2 Мемоизация RouteAt/wobble.** Кэш точных значений `RouteAt` +
   `HorizontalWobbleAt` по колонке (ключ — точный (x,z); хранится в
   thread-local сэмплере рядом с `CoarseHeightCache`). Это **не** аппроксимация —
   одни и те же колонки запрашиваются многократно разными стадиями, кэш отдаёт
   бит-в-бит те же значения → дрейфа нет. Инвалидация не нужна: параметры
   неизменны внутри генерации мира. Ожидаемый эффект: −30–50 % времени
   плотностных запросов.
3. **O-2.3 Окно скана вместо полной высоты.** Плотность = гладкая часть
   (`route.baseHeightBlocks` + региональные члены, вертикальный градиент ≈ −1)
   + ограниченный шум (амплитуда ≤ A_max, оценить консервативно по коду:
   `noiseFactor·FBM·0.55 + wobble`). Истинная поверхность лежит в окне
   `[smooth_crossing − A_max … scan_top]`. Заменить линейный скан: бинарный
   поиск пересечения гладкой части, затем линейный скан вниз от
   `min(scan_top, smooth_crossing + A_max)` окном `≈ 2·A_max+1` уровней.
   **Точность обязана быть бит-в-бит**: семантика «первый (сверху) y с
   плотностью > 0» сохраняется, если над окном гарантированно нет пересечений —
   консервативная граница A_max + assert в тесте.
4. **O-2.4 Parity-гейт.** Тест `density_surface_parity_test`: старый полный
   скан (эталонная функция рядом в тесте) vs оптимизированный путь на сетке
   колонок × seeds × профилями рельефа (океан/берег/равнина/горы), точное
   равенство. Включить в ctest.
5. **O-2.5 Замер + гейты.** Повторить замер шага 1 (цель: радиус-12 < 120 с;
   реалистично 2–3× ускорение). Попутно закрыть хвост P1-3: прогнать
   `tools/worldgen_quality_gates.py` + `tools/terrain_full_metrics.py` /
   `forest_metrics.py` на 10 seeds после переупорядочения mudflow (изменение
   порядка стадий могло сдвинуть метрики). Если гейты не проходят — откалибровать
   пороги по данным (отдельный коммит).
6. `CoarseSurfaceYAt` и `cavesInDensity`-ветка `SurfaceYAt`: не трогать в O-2.1–2.4
   (отдельная итерация, если профиль покажет их вклад).

Риски: неверная оценка A_max на горных профилях (jaggedness) → окно режет
редкие высокие пересечения. Защита: parity-тест на mountain-профилях обязателен,
A_max брать из `Params` (не константой).

## 2. P1.1: prune крон на швах чанков (инженерная реализация)

Единственный оставшийся дефект генерации листвы: колонки крон, попадающие в
чужой чанк через capture-буфер, никогда не прюнятся никем (шов виден как
«срезанные»/парящие края крон). Коммит-тайм prune признан тупиковым (зависимость
от порядка применения, см. журнал работ §5). Рекомендуемый вариант:

**Вариант (а) — placement-time обрезка (рекомендуется).**
В `TryPlaceProceduralTree` (`ObjectFeaturePlacer.cpp`, цикл приёмки :747-782)
для каждого canopy-вокселя, чья колонка лежит **вне** footprint'а чанка
(`FloorDiv(wx,16)` или `FloorDiv(wz,16)` ≠ чанк), сверять `voxel.y` с
`ctx.CoarseSurfaceYAt(wx, wz)` (детерминированная функция от seed, уже
подключена в контексте): если `voxel.y < neighbor_surface + 1` — чужой террейн
погребёт эту клетку, воксель отбрасывается сразу. Свойства: чистая функция от
seed → порядок генерации не влияет; стоимость — один coarse-запрос на
пограничный воксель (кэш высот уже греется вокруг чанка, `BeginChunkCoarseCache(pad)`).
Шаги: (а1) реализация + (а2) регресс-тест в интеграционном suite — крона у шва
одинаково обрезана при обоих порядках генерации соседей (расширение паттерна
`TestCrossChunkTreeConflictStable`, с террейном в scratch); (а3) кадры шва
до/после (`CUBA_FLIGHT_CAPTURE_DIR`, без тумана) + контроль плотности крон
`tools/forest_metrics.py` (обрезка не должна проредить лес за пределами швов).

**Вариант (б) — provenance + deferred prune по барьеру «колонка заселена».**
Резервный, если (а) даст видимые «ступени» на кронах. Требует: биты провенанса
в UChunk (не персистятся), барьер «колонка целиком заселена», void-маркировку
против повторного заполнения; подробно причины тупика — в журнале работ.

## 3. O-4: prefab id-drift

Проблема: `ResolveObjectVoxelPlacementId` (`ObjectUtil.cpp:65-78`) при
неразрешимом имени вокселя откатывается на **сырой `voxel.Id`** из
`objects/*.json`. После изменений распределения стабильных id паков
(`tools/assign_pack_block_ids.ps1`, регенерации assetgen) старые prefab-миры
и старые JSON объектов могут ссылаться на чужие блоки.

Шаги:
1. **Аудит данных**: скрипт `tools/check_object_voxel_ids.py` — для каждого
   вокселя всех `objects/*.json` сверить `Id` с текущим
   `GetPackBlockIdByTypeName(type_name)` по мержу паков; отчёт о расхождениях.
   Коммит со списком расхождений (без правок данных).
2. **Диагностика в рантайме**: при срабатывании fallback на сырой id —
   одноразовый (по id) `CubatariumLogInfo` с именем объекта/вокселя.
3. **Нормализация при загрузке**: в загрузчике объектов резолвить воксели по
   имени при парсе; неразрешимые — лог WARNING + null-воксель (не сырой id).
   Для старых миров изменение поведения при загрузке не требуется (id читаются
   как есть из сохранения), но новые генерации перестают тиражировать мусор.
4. **Тест**: юнит с фейковым object JSON (stale id + резолвимое имя) →
   размещённый блок равен резолвнутому id.
5. **Данные**: перегенерировать затронутые `objects/*.json` через assetgen
   (если шаг 1 найдёт расхождения), прогнать `validate_object_features.py --strict`.

   `tools/analyze_hole_event_pixels.py` / `analyze_screen_ray_parity.py` →
   получить конкретный воксель-свидетель и луч.
2. По witness'у сравнить CPU-мешер (`NeighborHidesFace`) и GPU-путь
   (`shaders/compute`, `MergeOpaqueQuadsStrict`/MDI-диапазоны) для той же пары
   блоков; посмотреть порядок remesh после relight на стыках секций по Y.
3. Кандидаты (по приоритету): (1) пропуск MDI-диапазонов при перераспределении
   вершинного пула, (2) `gpu_frustum`-отсечение под-диапазонов, (3) remesh-ревизии
   на стыках Y-секций.
4. Минимальный репро: расширить `greedy_cross_plant_ground_face_test`-паттерн
   на GPU-путь (если witness подтвердит CPU/GPU расхождение) — иначе фикс в

Время непрогнозируемо (расследование уже останавливалось дважды) — идти
