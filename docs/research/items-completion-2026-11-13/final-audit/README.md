Новые тесты публикации создают собственный staging во временном каталоге:
они не зависят от результатов предыдущей локальной генерации и не меняют

Python 3.11 в CI устанавливается до аудитов и конфигурации.

## Style и границы модулей

- `audit_style.py`: **0 замечаний** вместо 87 зафиксированных ранее.
- `check_include_rules.py`: **0 запрещённых новых рёбер** вместо 18.
- clang-format: **137 файлов**, включая новые и перенесённые заголовки.
- **8 тестов аудиторов** проверяют комментарии, строки, raw literals,
  предварительные объявления, реальные нарушения и сохранение проверки роста функций,
  отсутствие formatter и недоступную базу сравнения git.

Исправлены реальные имена классов/полей; разросшиеся функции разделены на
подготовку, обработчики, диагностику и завершение. Flight QA и галерея имеют
отдельные функции/состояние; native-пробы находятся в `src/Test/Native`.
Численные пределы grandfathered-функций не повышались. У существующего
mesh-oracle перенесён только ключ пути вслед за его реализацией.

Общие контракты граней, публикации и швов перенесены в `World/Math` и
`World/Mesh/Contracts`, данные воды — в `World/Fluids`, параметры вида — в
`World/View`. Это реальные объявления данных, а не заголовки-переадресаторы.
GPU-счётчики читаются через `UWorldMeshService`, mesh-oracle находится в mesh-адаптере.
Новых исключений include-аудита не добавлено; устаревшие записи удалены.

Гейт сохраняет **38 разрешённых legacy-включений** и информационную обратную
опись из **42 рёбер** Render→World. Это существующая политика аудитора, а не
утверждение о полной развязке движка. Дальнейшее устранение этих зависимостей
и оставшихся крупных grandfathered-функций относится к архитектурному backlog.

## Воспроизведение

```
cmake --build build/desktop-msvc --config Release --target Cubatarium --parallel 8
python tools/run_items_acceptance.py --extended --world ItemsCompletionQA
python tools/audit_style.py
python tools/audit_clang_format.py --base HEAD^
python tools/audit/check_include_rules.py
```

Проверка formatter требует установленного `clang-format` и доступного родителя
проверяемого коммита. В CI checkout использует `fetch-depth: 2`.

`--extended` собирает и запускает все 20 использованных целей. После уже
выполненной сборки допустим `--skip-build`. Мир должен быть отдельным QA-миром;
сценарий изменяет его арену. Загрузка и кадры выполняются через
`tools/flight_sim_run.py` с `bin/Cubatarium.exe`.

Рядом сохранены JSON-результаты, логи, исходные замечания и кадры. Основной
отчёт `../README.md` обновлён по этой приёмке.
