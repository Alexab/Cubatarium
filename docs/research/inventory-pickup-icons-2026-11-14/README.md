# Подбор блоков, счётчики и готовность иконок

Продолжение `inventory-ownership-refactor`, основание `86d4f8791`.

## Подбор и попадание

Обычный брошенный блок сохраняется после нанесения урона: это утверждённая
политика обычных предметов. Попадание не превращает блок в расходуемый снаряд.

Потеря количества при подборе в воспроизведённых сценариях не подтвердилась.
Обнаружен недостаток отображения: модель быстрых панелей не передавала количество,
а слот рисовал только номер клавиши. Кроме того, каталог Creative показывает
шаблоны, тогда как подобранные вещи хранятся отдельными конечными стеками в разделе
«Рюкзак». Ссылка каталога и конечный стек одного блока не объединяются.

Исправления:

- Количество конечного стека передаётся в модель панели и рисуется отдельно от
  номера клавиши: на основных/дополнительных панелях, панели каталога и в RH.
- У бесконечных записей нет числового счётчика и надписи `inf`, включая каталог,
  общий рюкзак и прежний экран Survival inventory.
- Подсказка каталога прямо указывает, что подобранные вещи находятся в Backpack.

Native-проверки добавлены для повторного подбора блока после попадания и промаха
в обоих режимах: конечное количество и snapshot рюкзака увеличиваются до двух.
Отдельно проверен Creative с шаблоном того же блока: 63 → 64, две единицы остаются
на земле при заполненном инвентаре; после освобождения слота остаток подбирается.
Числа на панели соответствуют конечным стекам, у шаблона счётчик пустой.

## Иконки

Причина задержки: готовые текстуры блоков публиковались в слотах только после
опустошения всей очереди. Большой каталог мог оставить уже готовые иконки скрытыми
до повторного открытия. Для предметов действовало сходное ожидание полной очереди.

Теперь готовые иконки подставляются каждый кадр. Видимые слоты имеют приоритет:
до четырёх непосредственных запросов за обновление, оставшийся бюджет блоков
используется для фоновой очереди. Объекты, существа и облики также заполняются
в видимой области, без массового синхронного рендера всей сетки. Неудачная иконка
не блокирует остальные: курсор обработки циклический. При смене вкладки старая
сетка не используется для прогрева нового вида содержимого.

Native-проверка очищает кэш блоков и требует увеличения числа готовых иконок
между обновлениями при всё ещё непустой фоновой очереди, без закрытия окна.
Пока иконка не готова, слот показывает название содержимого, а не пустую ячейку.
Слоты вне области прокрутки исключены из отрисовки; при прокрутке их видимость
пересчитывается. Большой каталог больше не отправляет на отрисовку всю сетку.
Отсечение выполняется только при рисовании: layout и расчёт высоты прокрутки
продолжают учитывать все записи. Native-тест проверяет переход к другим слотам
колесом мыши и возврат к исходной странице.

## Приёмка

```text
python tools/run_items_acceptance.py --extended --world CarryAimQA
```

Desktop — исключительно Release, точная команда сборки:

```text
cmake --build build/desktop-msvc --config Release --target Cubatarium --parallel 8
```

Результаты и native-кадры сохраняются в `evidence/` и `visual/` рядом с отчётом.
Итоговый прогон: Release CTest **21/21**, gameplay **51/51**, ownership/pickup
**57/57**, input/catalog **18/18**, layout **24/24**. Style/include/clang-format
проходят. Кадры сняты через `tools/flight_sim_run.py` с `bin/Cubatarium.exe`.
Проверки UI включают 1280×720 / 1920×1080 и масштабы 100/150/200%.
Холодная генерация иконок остаётся постепенной; отображение готовых результатов
больше не зависит от окончания всей очереди или повторного открытия окна.
