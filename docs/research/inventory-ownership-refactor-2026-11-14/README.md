## Результат

Принятый системный рефакторинг реализован. Конечные вещи физически перемещаются,
каталог материализует экземпляры. Creative добывает и подбирает конечную добычу.
Обычные брошенные предметы сохраняются после попадания и промаха. Захват существ,
ресурсные цепочки, общая баллистика и оригинальные модели сохранены.

| Область | Реализация |
|---|---|
| Владение | Два независимых банка по 40 слотов, экипировка и recovery; явные finite/catalog, несовместимые при объединении |
| Операции | Проверка режима и ревизии источника; пробное извлечение, публикация физического груза, фиксация; экипировка без потери экземпляра |
| Creative | Мгновенная добыча, конечный лут и подбор; бесплатные установка/рецепты/боеприпасы отделены от переноса имущества |
| Ёмкости | Изменение содержимого ссылки каталога материализует конечный экземпляр в том же слоте |
| Домены | Дропы сохраняют Creative/Survival; смена режима не меняет происхождение; мир установленных блоков общий |
| Смерть | Единый обработчик погибшего NPC, однократная награда, конечное имущество обоих банков; контекст действия фиксируется при выпуске |
| Броски | Явные категории 70 предметов; Free/Restricted/Custom в настройках мира; проверки до извлечения и при замахе/отпускании |
| Контакт | Сохраняются экземпляр, износ, поломка и содержимое; после попадания в воздухе предмет падает; покой не наносит повторный урон |
| Подбор | Задержка и отделение от коллизионного объёма бросившего; частичный подбор с остатком; нет удаления Creative-копий |
| Существа | Авторитетная связь переноски и заряд в физическом теле; ограничения рук/массы/размеров, сопротивление, возврат AI; Creative отменяет усталость |
| Нагрузка | 512 активных тел, ограниченная активная очередь; сохраняемые спящие/отложенные дропы; объединение совместимых неподвижных стеков одного домена |
| Сохранения | Inventory v4, physical v2, резервные копии, recovery; общая имущественная генерация с контрольной суммой, завершением и предыдущей генерацией |
| Окно игрока | E: каталог Creative / рюкзак Survival; B: тот же каталог; общая навигация, одно активное окно; обычный клик RH/LH, отдельные Drop и удаление назначения |

Удалены runtime `creativeCopy`, отрицательные количества, универсальная цель
переноса `PaletteGrid` и прямое начисление лута ResourceEconomy. Старые формы
читаются только при миграции. Источник каталога в drag-and-drop остаётся источником.

В ограниченном режиме разрешены блоки, материалы и специальные метательные
предметы. Запрещённую к броску вещь можно переносить и спокойно разместить.
Изменение правил отменяет недопустимый замах с сохранением груза. Существа
сохраняют отдельные физические ограничения. Управление: V — захват/размещение,
удержание и отпускание R — замах/бросок; Escape — отмена замаха.

## Дефекты, устранённые при итоговой проверке

- Немедленный обратный подбор Drop: отделение считалось от ног вместо центра
  коллизионного объёма. Выход из рук проверяется до списания конечного источника.
- Удаление назначения использовало устаревший режим в snapshot; UI теперь получает
  текущий режим мира.
- Последняя конечная стрела теряла идентичность при расходе. Теперь применяется
  Take; бесплатная материализация Creative отделена.
- Два несогласованных поля замаха заменены каноническим состоянием физического
  тела; поле персонажа служит проекцией для анимации.
- Проверки бюджета считали записи вместо единиц имущества; теперь подтверждают
  сохранение количества при агрегации и после сериализации.
- Поиск неизвестного блока создавал синтетическое определение. Проверка наличия
  теперь не создаёт его; запись сохраняется в recovery соответствующего режима.
- Повреждённые физические записи сохраняются целиком; дубликат в карантине не
  воскресает после расходования оригинального экземпляра.
- Ошибка записи users/creatures не позволяет опубликовать завершённый имущественный
  снимок из старых файлов. Добавлена резервная копия старых physical v1 данных.
- Native-кадры выявили перезапуск постепенной загрузки большой сетки блоков каждый
  кадр: каталог был пустым несмотря на наличие данных. Загрузка теперь продолжается
  между кадрами; native-проверка требует полного завершения большой сетки.
- Частичное получение из recovery теперь выдаёт остатку глобально уникальный ID,
  исключая пересечение с экземплярами другого владельца.

## Release и воспроизводимость

Desktop собирался исключительно в Release:

```text
cmake --build build/desktop-msvc --config Release --target Cubatarium --parallel 8
python tools/run_items_acceptance.py --extended --world CarryAimQA
```

Runner проверяет коды выхода, удаляет старые итоговые JSON перед native-запуском и
требует свежие успешные gameplay/window/ownership/ownership-ui отчёты. Native
запускается через `tools/flight_sim_run.py` и `bin/Cubatarium.exe`.
CI дополнен Release-сборкой и профильными проверками; native-приёмка опциональна
для Windows runner с OpenGL desktop. Удалённый GitHub Actions здесь не запускался.

## Границы доказательств и backlog

- Имущественный snapshot согласует inventories и physical/creature data. Это не
  транзакция всех terrain chunks и не гарантия всего мира при аппаратном отключении
  питания. Проверены прерванная временная запись, повреждённая текущая генерация,
  возврат к предыдущей завершённой и отказ при повреждении обеих.
- Нагрузочная проверка воспроизводима на QA-мире. Многодневный стресс населённого
  мира и общий streaming soak остаются отдельной эксплуатационной работой.
- Layout и native-кадры подтверждают геометрию, ввод и рендер; они не заменяют
  пользовательское исследование удобства всех сочетаний.
- 38 разрешённых старых World→Render include и 42 обратные зависимости остаются
  общим учтённым долгом движка. Новых запрещённых include нет; Pipeline — 0.
- MSVC сообщает существующее предупреждение C4335 о переводах строк в
  `WorldBlockPhysicsService.h`; сборка завершается успешно. Нормализация этого
  отдельного заголовка не включалась в изменение поведения имущества.
- Species-specific IK, ragdoll, разрушение блоков броском и будущие расходуемые
  снаряды не добавлялись. Последним потребуется собственная политика контакта.

Открытых воспроизводимых дефектов в проверенных сценариях после итогового прогона
не осталось. Посторонние сохранённые изменения не применялись. Слияние в develop
и публикация не выполнялись.
