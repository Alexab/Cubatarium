# Sand / stone / dirt monsters — fidelity v2

Три вида приняты Codex по прямому просмотру точных native, comparison,
world и UI artifacts; это не подпись пользователя. `review.json` закрепляет
хеши конкретных ресурсов и доказательств. Это R5, не завершение общей цели.

## Собственный вид при знакомых пропорциях

У песчаного монстра восстановлены длинные ноги, узкий корпус, маленькая
голова, песочная палитра и бирюзовый верхний акцент. У каменного/земляного —
исходные более широкие плечи, прямой корпус и отдельные длинные конечности.
Все материалы нарисованы по собственным полям в анатомическом пространстве:
волнистые слои песчаника, спокойные серые трещины и прожилки, коричневая
глина с небольшими включениями. Пиксели и геометрия baseline не копировались.
Первоначальные слишком светлые пятна камня и большие глаза уменьшены
после сравнительного просмотра. Материал больше не заменяет анатомию.

Размеры в блоках (X/Y/Z):

| Вид | Baseline | Собственный |
|---|---|---|
| sand_monster | 0.593625 / 1.864753 / 0.394657 | 0.59375 / 1.875 / 0.375 |
| stone_monster | 0.804589 / 1.724323 / 0.418808 | 0.8125 / 1.75 / 0.4375 |
| dirt_monster | 0.804589 / 1.724323 / 0.418808 | 0.8125 / 1.75 / 0.4375 |

Gameplay bounds, скорости и habitat не менялись. Baseline sand имеет чёрные
грани не только в offline renderer: это воспроизведено в настоящем Release,
`../creature-monster-baseline-v2/native_baseline`. Такой дефект не переносится
в собственный atlas. Общие baseline-листы 13 монстров исследовательские,
они не принимают их текущий production-вариант.

## Риг, движение и контакт

Каждый кандидат имеет 17 действительно взвешенных joints против одного
weighted joint у исходного glTF (palette 18/7/7). Сохранены idle/walk/run/punch;
die в оригинале не было. Отдельные spine/neck/head/jaw, плечо/локоть/кисть,
бедро/колено/стопа. Удар выводит обе кисти вперёд, корпус наклоняется,
челюсть двигается; Run увеличивает амплитуду и сгибание коленей.

Верхние сегменты рук/ног разделены на две геометрические секции. У корня
вес переходит к корпусу, у дистального кольца — к локтю/колену. Так оба
стыка остаются закрыты, вместо щели на одном конце куба с одной blend-зоной.
Тест проверяет совпадающие вершины после полного skinning и удержание
проксимального кольца на родителе при Walk/Run/Punch. Внутренние горизонтальные
caps разделённых сегментов могут пересекать грудную секцию; наружных
совпадающих боковых плоскостей, вызывающих flicker, нет.

Контакт рассчитан по геометрии стоп в каждом ключе. Диагностика 65 фаз
Walk/Run/Punch/Idle показывает minY=0 в точности округления 1e−6 блока.
Тест также проверяет подъём при переносе и правильный откат при опоре.
Частота Walk/Run согласована с фактическим ходом стопы: при единичном
runtime travelScale скорость опорного отката равна штатной walk_speed.
Это предотвращает скольжение, которое не ловится проверкой одного знака.
Скорость обычного AI не изменялась; настроен только playback ресурса.

Движок масштабирует playback по actual_speed / walk_speed, ограничивая
travelScale диапазоном до 1.5 и минимальной ненулевой частотой .22.
Проверка этих границ, других видов и переходов состояний остаётся R6.
В частности, короткий asset duration сам по себе не означает быстрый Run:
смотреть нужно duration/runtime_speed и фактическую скорость движения.

## Доказательства

- `<id>.png`: три поколения модели, шесть ракурсов, одна мировая шкала.
- `native_approved_<id>.png`: настоящие четыре стороны и по восемь фаз
  locomotion/Run/Action текущего Release; имя файла не заменяет решение review.
- `icons_final.png`: настоящие 64px UI render, увеличенные nearest neighbour.
- `runtime_cadence_<id>/frame_002.png`: финальная модель в мире.
- `context_cadence_<id>.json`: точный payload, runtime definition, exe/shaders.
- `metrics.json`: actual skinning/contact/extents/clip periods.
- `rig_capability_audit.json`: исходные и новые возможности.
- Ранние `pilot_*`/`final_*` captures предшествуют калибровке cadence;
  они диагностические, не окончательное evidence.

Проверки: 30 fidelity и 9 quality Python tests, Release приложение.
Девять выбранных C++ tests повторно проходят после публикации.
Каждый вид повторно действительно создан через `--production`, без QA-подмены
моделей; сохранены свежие relocation dumps и контексты с
`qa_models_override:false`. Все 87/87 native-кадров пиксельно совпали
с принятыми кандидатами; production-world кадры прямо просмотрены.
`production_preview_parity.json` фиксирует совпадение; payload в `models/`
и `bin/models/` сверены с точными принятыми bundle hashes.
Восьмисекундные flight
probes не имеют performance gates; performance PASS не заявляется.
Полная R6-матрица compatibility/save-load/FP/equipment, платформы, маршруты,
производительность и воспроизводимость всех 61 ресурсов ещё не выполнена.
