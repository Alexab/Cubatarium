# Существа: план доработок и исправлений (2026-10-29)

Источник: замечания пользователя после этапов 1–4 из `CREATURES_RUNTIME_AUDIT_2026-10-29_RU.md`.
Статус: **план, код не менялся**. Все цифры ниже получены анализом файлов моделей и кода;
помеченное «гипотеза» ещё не подтверждено запуском.

## 0. Главная находка: коллизионная коробка не совпадает с видимым телом

Для 33 glTF-существ я сравнил размеры меша в `model.gltf` (с `model_scale`) с `bounds.rest`
из `creature.json`. Коробка задаёт коллизию, посадку, попадание, спавн; меш задаёт то, что видит игрок.

| Существо | Высота меша | Высота коробки | Ширина меша / коробки |
|---|---|---|---|
| water_dragon | 5,7 | 1,0 (×5,7) | 2,88 / 2,2 |
| treeman | 4,87 | 1,75 (×2,8) | 1,83 / 0,65 (×2,8) |
| whale | 3,31 | 1,2 (×2,8) | 11,0 / 4,0 (×2,75) |
| ogre | 3,14 | 1,75 (×1,8) | 2,86 / 0,65 (×4,4) |
| orc | 2,74 | 1,75 (×1,6) | 1,85 / 0,65 (×2,8) |
| mese_monster | 1,12 | 1,75 | 2,97 / 0,65 (×4,6) |
| manatee | 0,93 | 0,45 (×2,1) | 3,83 / 1,35 (×2,8) |
| owl | 1,56 | 0,65 (×2,4) | 0,64 / 0,55 |
| wasp | 0,98 | 0,35 (×2,8) | 0,83 / 0,6 |

Оговорка: это экстенты позы привязки (bind pose) из accessor min/max, не позы анимации.
Нужна проверка в игре, но порядок величин объясняет сразу пункты 1, 3 и 7.
Нормальные соответствия (ratio ≈ 1): dirt_monster, stone_monster, sand_monster, fire_spirit,
kitten, hedgehog, penguin, panda.

**Системное решение (общее для 1, 3, 7):**
1. Инструмент аудита `tools/creature_bounds_audit.py` (+ тест в CI): сравнивает меш×scale с `bounds`,
   падает при расхождении больше порога (предлагаю ±25 % по высоте и ширине).
2. Единый источник истины: либо `bounds` выводится из меша при загрузке (`_derived` уже есть у
   `rigid_demo_*`), либо `model_scale` подбирается под `bounds`. Решение принимает автор
   контента: что считать эталоном, коробку или внешний вид.
3. Для существ с большим расхождением — исправить данные (scale/bounds) по таблице выше.

## 1. На высоких мобов нельзя сесть, проваливаюсь внутрь

Причина (вероятная): у «супер-высоких» 3D-существ (treeman, ogre, water_dragon, whale…) видимое
тело в 1,8–5,7 раза выше коробки, поэтому игрок «стоит» на невидимой верхней грани, а визуально
оказывается внутри тела. Мои прогоны ездой проверяли только корову (1,3), зомби в стенде не
воспроизведён (всадник упал в 3 блоках от моба, `dxz=3`).

План:
- 1.1 Исправить данные по §0 (основная починка).
- 1.2 Расширить стенд `CUBA_FLIGHT_QA_RIDE`: ставить всадника строго над центром моба (сейчас
  `dxz=3`), прогонять по всем видам из таблицы, фиксировать `mountFound`, `feetY - mobTop`.
- 1.3 Параметры `FindMountUnder` (допуск 0,6 вниз / 0,5 вверх) привязать к высоте моба, чтобы
  для высоких существ посадка не зависела от жёстких констант.
- 1.4 Регрессионный тест: для каждого вида из каталога всадник, брошенный сверху, садится.

## 2. На мобов можно ставить блоки

Причина: `UWorldCollision::CanPlaceClassic` (через `ResolveBlockPlacement`,
`src/World/Collision/WorldCollision.cpp:1131`) проверяет только капсулу игрока и блоки, существа
не учитываются.

План:
- 2.1 В `CanPlaceClassic` отклонять постановку, если AABB целевой клетки пересекает коллизионный
  объём любого существа (`UWorldEnvironment::CheckCreatureCollisionVolume`, уже есть и использует
  пространственный индекс), кроме существа, на котором сидит игрок.
- 2.2 Решить с автором геймдизайна: блок вплотную к мобу допустим (пересечение = отказ,
  касание = можно). Предлагаю так.
- 2.3 Юнит-тест на `ResolveBlockPlacement` с существом в клетке и вне её.
- Зависимость: полезность проверки зависит от §0 (коробка должна соответствовать телу).

## 3. Некоторые мобы остаются проходимыми

Причины-кандидаты (гипотезы, по убыванию вероятности):
1. Коробка меньше видимого тела (см. §0): ogre, mese_monster, treeman, orc, manatee, whale
   проходимы «по краю» тела, хотя коллизия формально работает.
2. Мобы, отключённые заморозкой чанка (`cfc766af6`) или вне радиуса активности, могут иметь
   устаревшую позицию в `UCreatureSpatialIndex` (индекс обновляется через `Upsert` только у
   обработанных существ).
3. Коллизия игрока с существами зависит от `EntityCollisionEnabled`.

План:
- 3.1 Добавить **отладочную подпись над головой** (запрошено): `Species #id` + флаги
  `coll=вкл/выкл`, `idx=в индексе/нет`, `box=WxHxD`. Включается настройкой
  `gameplay.creature_debug_labels` (по умолчанию выкл) и консольной командой.
  Реализация: `UCreatureDrawPass` + текстовый рендер в мировых координатах (проекция по камере).
- 3.2 По подписям и таблице §0 установить точный список и причины, затем чинить по каждой.
- 3.3 Проверка согласованности индекса: в отладочном режиме сверять `Tracked` индекса с
  `GetCollisionVolume()` каждого существа раз в N кадров, логировать расхождения.
- 3.4 Тест: для каждого вида игрок, идущий в моба, останавливается на границе коробки.

## 4. Автоповорот пассажира выключить по умолчанию

Простое изменение значения по умолчанию `gameplay.ride_carry_yaw`: `true → false` в
`src/App/Core.h:226`, `src/App/Core.cpp:312` (чтение), `src/App/Settings/AppSettingsSnapshot.h:21`,
`src/World/Core/World.h` (`RiderYawCarryEnabled{true}`), обновить `RiderCarryTest`/документацию.
Существующие конфиги, где ключ уже записан как `true`, останутся как есть — сообщить пользователю.
Опция остаётся в настройках.

## 5. Освещение не действует на существ

Причина: `shaders/fshader_creature.glsl` и `fshader_creature_skinned.glsl` выводят только
`texture * uTint`. Нет ни дневного/ночного коэффициента, ни локального света блоков, ни тени.

План (по возрастанию сложности и пользы):
- 5.1 **Дневной/ночной коэффициент**: общий uniform `uAmbient` из `World::DayNightFactor` /
  `MoonNightFactor` (уже есть в `World.h:262`) и минимальной яркости ночи. Даёт эффект «ночью темнее».
- 5.2 **Локальный свет**: раз в N кадров CPU считает упакованный свет (sky + block) в клетке центра
  тела существа (API света чанка `GetLightPackedLocal` уже есть) и передаёт `uLight` в шейдер, с
  плавной интерполяцией по времени, чтобы не мигало на границах клеток. Пещеры и факелы работают.
- 5.3 Единые константы яркости с блоками (кривая освещения из `fshader_greedy.glsl`), чтобы существа
  не выглядели светлее/темнее мира.
- 5.4 Учесть вспышку урона (`ActiveHitFlash01`) — она сейчас в `uTint`, должна остаться поверх света.
- 5.5 Применить ко всем бэкендам (`gltf_skeleton`, `bone_skeleton`, `rigid_voxels`, `sprite`) и к
  GLES-вариантам шейдеров.
- Проверка: скриншоты в день/ночь/пещеру в стенде; тест на формулу коэффициента.

## 6. Некоторые существа стоят на месте («утка»)

Факты:
- Вида «duck» в каталоге нет (56 определений). Пользователь, вероятно, имеет в виду chicken, puffin
  или penguin; chicken есть в каталоге, но без `model.gltf` (другой бэкенд).
- Не понятно, баг или совпадение; ранее «зависания» оказывались артефактом стенда (камера улетала,
  чанки выгружались и срабатывала заморозка из `cfc766af6`).

План:
- 6.1 Подпись над головой (§3.1) показывает вид и состояние (`state`, `speed`, `idleTimer`,
  `stuckTimer`, `frozen`).
- 6.2 Поведенческий QA в стенде для chicken/puffin/penguin: доля времени в `Walk` за 60 с,
  смещение за минуту; порог «стоит» < 1 блока за минуту.
- 6.3 Разобрать причины по подписи: заморозка чанка, `forward_probe_fail` (мало места), амфибийная
  логика (puffin/penguin: вода/берег), `wander_interval`.
- 6.4 Если причина в данных (скорость 0, неверный `habitat`) — поправить `creature.json`.

## 7. Сова летает вместе с «подставкой» под лапами

Факты из `models/creatures/owl/model.gltf`:
- В основном примитиве есть плоская пластина: 8 вершин на y = 0, x от −0,316 до −0,231, z от
  −0,129 до 0,119 (тонкая «планка» шириной 0,085, смещённая в сторону от тела). Похоже на
  жёрдочку/подставку из исходной модели.
- Высота меша 1,56 при коробке 0,65 (×2,4), `model_scale = 1.0`: сова визуально в 2,4 раза выше
  своей коробки.

План:
- 7.1 Просмотреть модель в превью (`UContentPreviewRenderer`) и подтвердить, что пластина — подставка.
- 7.2 Удалить подставку из `model.gltf`/`model.bin` (вершины y < 0,12 примитива 0, перестроить
  индексы), либо скрыть её по имени материала/ноды, если она отдельный узел. Скелет и анимации
  (`walk`, `idle`) не затрагивать.
- 7.3 Подогнать `model_scale` или `bounds` по §0 (владелец решает, что эталон).
- 7.4 Аудит остальных птиц и моделей на подставки (puffin, penguin, wasp, bee): искать плоские
  группы вершин на минимальной высоте в стороне от тела.
- 7.5 Тест целостности модели (расширение `CreatureModelIntegrityTest`): запрет плоской
  изолированной группы вершин у нижней границы.
