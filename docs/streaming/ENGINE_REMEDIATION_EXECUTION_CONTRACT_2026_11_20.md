# Конечный порядок завершения S0..S6

Этот документ уточняет существующие WORK_PACKAGES и FINISH_CHECKLIST, не заменяет исходные требования и evidence index. Текущий пакет S4.01. Закрыто 22 из 42 пакетов: S0.01–05, S1.01–05, S2.01–06, S3.01–06. Остаётся 20. Родительские этапы закрываются после итоговой сверки доказательств, а не автоматически по числу пакетов.

## Обязательный порядок работы

1. Открыть один пакет и сопоставить его требования с существующими доказательствами. Не повторять уже доказанные проверки без изменения зависимого кода.
2. До реализации записать недостающее свойство, production owner, фиксированную сцену, ожидаемый результат, команду и timeout.
3. Получить одну адресную репродукцию. Если её нет, сохранить находку как подозрение; не объявлять дефект доказанным.
4. Исправить конкретный owner. Выполнить адресную проверку и необходимые зависимые проверки.
5. При повторном падении разобрать артефакт до нового запуска. После двух неудачных гипотез составить карту producer → queue → owner → install → consumer и выбрать проверку последнего неизвестного перехода. Обзорный полёт не является локализацией.
6. Достаточный PASS завершает пакет: evidence index, commit, ограничения, следующий пакет. Посторонние находки идут в DEFECT_QUEUE; немедленное переключение допускается только при блокировке текущего результата либо угрозе потери данных.
7. Если обязательный backend или возможность отсутствуют, записать конкретную недостающую реализацию и зависимые пакеты. Не повторять неподходящие тесты в ожидании PASS. Продолжать независимую работу; обязательство остаётся открытым.

## Завершённый пакет S3.04

Восемь действий ниже завершены; доказательства сведены в S3_04_STALE_INSTALL_MATRIX и S3_04_CANCEL_DEBT_CARD. S3.05 и S3.06 также завершены: persisted contract и actual GPU/CPU/fallback доказательства в соответствующих карточках. Следующий S4.01: текущие секционные переходы, один owner каждого состояния, replacement incarnation и повторный demand. Не повторять закрытые доказательства без изменения зависимого кода.

1. Свести существующие проверки read-set, каталога, профиля, world epoch и incarnation в таблицу sync/async; отметить только пробелы.
2. Проследить реальные `EnqueueJob`, `DrainCompleted`, `CancelPending`, overflow и обработчики UWorld. Указать владельца полного задания после каждого перехода.
3. Проверить подозрение: отмена очереди может уничтожить задание, а восстановление только по source positions может потерять Y-band, domains и AIR targets. Это пока гипотеза, не подтверждённый результат теста.
4. Сделать детерминированную проверку реального worker lifecycle для queued/running/completed cancellation; порядок задаётся барьером, а не случайным sleep.
5. Если потеря подтверждена, сохранить полную спецификацию обязательства до terminal outcome. При quiesce не запускать новую работу немедленно; восстановление должно происходить через штатного владельца после возобновления.
6. Проверить stale между capture/compute/install отдельно от cancel: старое значение отвергается, точный преемник завершается.
7. Проверить отсутствие двойного возврата долга при позднем completion; overflow не теряет точный запрос; новый мир не получает долг старого мира.
8. Закрыть S3.04 только при доказанных rejection **и** завершении актуального преемника. Подготовить receipt и commit; перейти к S3.05. Общий аудит очередей остаётся S4.02.

## Контроль прогресса

После каждого пакета сообщать: закрытый результат, доказательство, остаток пакетов, следующий шаг и новый блокер, если появился. Не считать число тестов процентом готовности продукта. Прогноз уточнять на границах S3/S4/S5; до определения отсутствующих backend и переноса мира календарный срок не является надёжным.

Все сборки и запуски — Release. Native проверки — на изолированной копии мира штатным flight runner; исходные мир и config сохраняются. Полная финальная матрица выполняется после реализации зависимостей. Интеграция веток, если потребуется, только merge commit `--no-ff`.

## Уточнённые исполнимые шаги от текущей точки

Это декомпозиция оставшихся 20 пакетов, а не новые требования. Уже закрытые 22 пакета и доказательства не пересматриваются без изменения зависимого кода. Отсчёт ниже — действия, не процент готовности. В каждый момент исполняется один шаг. Исходные требования и stage exit gates имеют приоритет над краткими формулировками.

### S4 — завершить управление состояниями и сохранениями

1. **S4.01 / job-stage.** На фиксированной секции с устаревшим физическим светом проверить `SyncColumnJobStageFromWorld`: отсутствие очередей не должно давать LitReady. Исправить проекцию, проверить восстановление после актуального расчёта.
2. **S4.01 / callback публикации.** Проверить обход light gate через coarse LitReady/Meshing в `ChunkEmergeCoordinator`. При публикации одной секции незавершённый сосед не должен подтверждать весь столбец.
3. **S4.01 / render-ready.** Разделить разрешение рисовать имеющееся представление и подтверждение завершённой актуальной публикации. Проверить pending GPU, старую публикацию и актуальную завершённую секцию.
4. **S4.01 / закрытие.** Свести перечисленные переходы в существующую owner-card; проверить replacement/repeated demand существующими доказательствами. Закрыть пакет, если конкурирующих подтверждений в перечисленных путях нет. Атомарное переключение пары оставить S4.03.
5. **S4.02 / реестр очередей.** По существующей карте перечислить реально используемые очереди: ключ, владелец обязательства, лимит, coalescing и terminal outcomes. Зафиксировать конечный список строк до fault-проверок.
6. **S4.02 / отказ и переполнение.** Для непокрытых строк проверить reject/overflow: исходное обязательство либо исполняется, либо возвращается штатному владельцу. Уже доказанный relight lifecycle не повторять.
7. **S4.02 / отмена и вытеснение.** Проверить непокрытые cancel/eviction/coalescing и завершение актуального преемника. Отдельно локализовать сохранённое подозрение terrain-arrival/fluid-map; исправлять только при подтверждении.
8. **S4.02 / закрытие.** Каждая строка реестра имеет terminal outcome и доказательство отсутствия потерянного обязательства; все найденные пробелы перечислены явно.
9. **S4.03 / перестановки.** Задать одну сцену и барьеры: geometry раньше field, field раньше geometry, поздний predecessor, replacement incarnation.
10. **S4.03 / переключение.** Исправить владельца публикации так, чтобы старая совместимая пара удерживалась до полной готовности новой; отвергать устаревшие компоненты.
11. **S4.03 / закрытие.** Все четыре перестановки дают совместимую пару и конечное продвижение; намеренная несовместимая пара обнаруживается проверкой.
12. **S4.04 / first paint.** Взять сохранённый сбой с 13 unready секциями; зафиксировать фактическое visible/fog множество и конкретный обход барьера.
13. **S4.04 / закрытие.** Исправить обход; задержанная обязательная секция запрещает первый кадр, её завершение разрешает его. Проверка не расширяется в обзорный полёт.
14. **S4.05 / блокеры.** Для незавершённой секции выводить identity, нужный input, очередь, executable owner и следующий переход. Проверить искусственно удержанный input.
15. **S4.05 / продвижение и стоимость.** На фиксированном непрерывном потоке проверить отсутствие starvation и границы обходов, включая новый column-light aggregate. Заранее определить размер нагрузки и измеряемый лимит.
16. **S4.06 / временный сбой.** Внедрить временный отказ записи; проверить тихий автоматический retry, сохранение dirty debt и конечную запись без действий игрока.
17. **S4.06 / fatal.** Внедрить disk-full/неустранимый отказ; остановить gameplay, выйти в меню, сохранить несброшенные правки и показать решение о месте сохранения.
18. **S4.06 / перенос.** Реализовать выбор каталога и перенос полного мира через staging, проверку полноты и переключение активного пути после успешного завершения.
19. **S4.06 / закрытие.** Проверить отмену выбора, отказ/прерывание переноса и успешный cold reload из нового места. До успешного переключения исходный мир остаётся пригодным для восстановления.
