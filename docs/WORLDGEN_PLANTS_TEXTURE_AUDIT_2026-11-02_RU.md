## 1. Два заявленных визуальных бага — причины найдены в коде

### 1.1 Листья неразрушимы (и трава/цветы — тоже)

Листва **не таргетится прицелом**, поэтому сессия копания даже не начинается.
Данные блоков корректны (`hardness: 0.2`, dig-группы на месте) — виноват raycast:

- `src/World/Raycast/BlockRaycast.cpp:37-47` — `IsRaycastTarget` возвращает
  `registry.BlocksMovement(q.id)`;
- `src/Blocks/BlockRegistry.cpp:247-254` — `BlocksMovement` = `Occupancy >= 1.0f`;
- все листья и cross-растения имеют `occupancy: 0.0` (проставляется конвейером:
  `tools/canonical_blocks.yaml:3-4` → `tools/stem_mapping_common.py:119-121`, а
  также `assetgen.py:5312-5328` для генерируемого пака) → raycast сквозь них.

Следствия: листву/траву/цветы нельзя сломать ни в Survival (таймер даже не
запустится), ни в Creative (мгновенное удаление тоже идёт через
`RaycastSolidBlocks`, `World.cpp:14851-14860`), нельзя выбрать их целью для
установки блока «вплотную». Луч проходит насквозь и ломает блок позади листвы.

В Luanti/Minecraft листья — не твёрдые, но «pointable»: у движка есть отдельное
понятие пригодности к прицеливанию, здесь его нет.

**Исправление (P0-1):** ввести предикат «диг-таргетable» и использовать его в
`IsRaycastTarget`: не AIR, не unloaded, не жидкость, и (`BlocksMovement(id)` ИЛИ
`Render.Style ∈ {Cutout, Cross}`). Более управляемый вариант — явный флаг
`pointable` в JSON блока, проставляемый `assetgen`/`apply_canonical_types`
(листва, cross-растения, стёкла — true; жидкости — false). Обязателен
регресс-тест на raycast по occupancy-0 блокам (сейчас тестов на таргетинг нет
вообще — проверены только длительности копания). Заодно проверить установку
блока на грань листвы/cross-растения и дроп предметов (`GrantBlockDrop`).

### 1.2 Листва висит в воздухе отдельно от дерева

Размещение дерева атомарно (ствол+крона пишутся только после полной валидации,
`ObjectFeaturePlacer.cpp:747-782`), «стволов без крон» пайплайн не создаёт.
Плавающая листва — результат трёх независимых дыр:

1. **Cross-border колонки никогда не прюнятся.** `PruneFloatingVegetationInChunk`
   (`WorldGenStages.cpp:923-941`) обходит только 16×16 колонок своего чанка.
   Крона дерева у границы пишет листву в соседние колонки через capture-буфер
   (`PipelineChunkPopulator.cpp:253-267`, применение — `ChunkBuffer::ApplyTo`,
   `ChunkLoadScheduler.cpp:552`). Эти колонки: (а) не свои у чанка-владельца
   дерева, (б) невидимы в scratch-мире соседа (он генерирует свой террейн
   отдельно) → их support-проверка не выполняется никогда. Плюс валидация
   cross-border вокселей идёт против пустого scratch (`!IsAir` не видит рельеф
   соседа). Итог: у швов кроны несимметричны — часть над своим чанком подрезана
   снизу эвристикой, часть над соседним висит как есть, в т.ч. «клубки» над
   воздухом.
2. **Нет leaf decay в геймплее.** После рубки ствола каскад
   `BreakUnsupportedBlocksAbove` (`ObjectUtil.cpp:786-836`) идёт только вертикально
   вверх одной колонкой и останавливается на первом solid (следующее бревно).
   Крона остаётся висеть навсегда — а убрать её вручную нельзя из-за бага 1.1.
   Поиск «decay» в `src/` подтверждает: фичи нет.
3. **Mudflow после деревьев.** `ApplyMudflowToChunk` (`PipelineChunkPopulator.cpp:564-574`,
   `MudflowErosion.cpp:30-117`) переносит верхний грунт уже ПОСЛЕ размещения
   растительности и может смыть опору под стволом («дерево на ножке»; ствол —
   solid, прюна его не трогает). Плюс mudflow ограничен чанком (соседей не видит,
   `:56-58`) → эрозия рвётся на швах.

Эвристика прюны: support = solid-блок строго ниже или по 4 диагоналям ниже
(`ObjectUtil.cpp:46-62`), фикспоинт снизу-вверх (`:839-877`) — внутри чанка
цепочки схлопываются корректно, но нижние «козырьки» крон срезаются (плоские
днища). Это косметика, не источник паразитной листвы.

**Исправления (P1):**
- P1-1 (главное): prune по факту применения входящих cross-chunk блоков.
  Принимающий чанк после `ApplyTo` чужого буфера знает затронутые колонки —
  прогнать `PruneFloatingPlantsInColumn` по ним в **живом** мире (террейн уже
  применён, support-проверка увидит реальный рельеф). Это закрывает и
  несимметричность крон, и «клубки над воздухом». Альтернатива дороже:
  размещать деревья с margin ±N через детерминированный `CoarseSurfaceYAt`.
- P1-2: leaf decay — минимально: расширить каскад до BFS-зачистки связной
  листвы вокруг сломанного блока (лимит по числу вокселей/радиусу кроны);
  канонично (MC-like): отложенное затухание листвы без лога в радиусе 4.
- P1-3: mudflow — перенести до стадии Vegetation либо после mudflow
  повторно проверять опору стволов; для швов — читать высоты соседей (кэш уже
  есть: `BeginChunkCoarseCache(pad)`).

## 2. Текстурный генератор и пак: главный разрыв

`tools/assetgen.py` (7198 строк, детерминированный offline-бэкенд Pillow+YAML;
ML/TripoSR — опционально) собирает пак `cubatarium_worldgen_cc0`
(1754 blocks/*.json, 2483 текстуры, стабильные id, `asset_manifest.json` с
sha256) + 64px overlay `cubatarium_worldgen_photo64_cc0`. Паки закоммичены в
git и являются источником истины; рантайм подхватывает их через
`ResourcePackResolver.h:52-62` → `ResourcePackBootstrap.cpp` →
`UBlockMergeRegistry`. Физика/свет берутся из JSON блока, а не из альфы PNG —
это согласовано.

**Находка P2-1 (главная):** сгенерированные cutout-листья `cu_organic_leaf_*`
(10 вариантов, 53.9% прозрачности у `dark`; результат всей серии экспериментов
LeafAlpha/ConnectedAlpha/FaceAware V24–V33) **не используются деревьями в мире**:

- профили worldgen-деревьев ссылаются на ре-экспорты Minetest:
  `mtg_leaves`, `mtg_aspen_leaves`, `mtg_acacia_leaves`, `leaves_spruce`,
  `mtg_bush_leaves` и т.д. (`content/object_features.json`; дефолт
  `tree_leaves` — `WorldGenSets.cpp:135`);
- `tree_leaves.json` использует стем `mt_leaves_opaque` на все 6 граней;
- `texture_overrides.json` не содержит ни одного remap на `cu_organic_leaf_*`;
- в `objects/*.json` (prefab-деревья) `cu_organic_leaf_*` тоже не встречается.

То есть вся работа по leaf-альфе осела в паке как orphaned-контент, а самые
заметные блоки мира рендерятся старыми re-export текстурами (у всех
проверенных `mt_*leaves*` ровно 39.8% прозрачных пикселей — явно один и тот же
масштаб вырезов, без вариативности).

**Исправление (P2-1):** подключить генерацию к потребителю любым из путей:
(а) remap граней через `texture_overrides.json` (`mtg_leaves` →
`cu_organic_leaf_*` по видам деревьев), (б) сменить `texture`/`leaves_block` в
профилях `object_features.json` + `ensure_worldgen_rules` в assetgen. Затем
контрольные кадры (лес/хвоя/акация, туман выключен) и обновление
`asset_manifest.json`. Дополнить `assetgen audit` проверкой «блок пака, на
который нет ссылок из worldgen/objects/overrides» — детектор orphaned-контента.

Прочее по пакам (без действий сейчас): builtin-ранги cross-chunk правил берут
глобальные имена (`ChunkBuffer.cpp:133-160`) — блоки кастомных паков получают
ранг 0 и считаются «террейном»; 101 блок вторичных паков с альфой без явного
режима (не используются worldgen); TD-002 (инкрементальный атлас) и TD-006
(Android) — подтверждённый бэклог `docs/TECH_DEBT_RESOURCE_PACKS.md`.

## 4. План доработок (по приоритету)

**P0 — геймплейные блокеры (быстрые, точечные)**
1. Таргетинг не-solid блоков: предикат «pointable» в `IsRaycastTarget`
   (`BlockRaycast.cpp:37-47`) + флаг/стиль-правило в данных; регресс-тест
   «raycast попадает в occupancy-0 листву и cross-растение, не попадает в
   жидкость»; смоук `flight_sim_run.py` + ручная проверка ломания/установки.
2. BFS-зачистка листвы при рубке (минимальный leaf decay) с лимитом размера;
   тест: срубил ствол — крона исчезла; срубил ветку — кусок кроны исчезает.

**P1 — генерация листвы (швы чанков)**
3. Prune входящих cross-chunk колонок после `ApplyTo` в живом мире (P1-1);
   регресс-тест на пару соседних чанков: крона у шва одинаково подрезана с обеих
   сторон, над воздухом не висит (расширение
   `WorldGenVegetationPlacementIntegrationTest`).
4. Mudflow до Vegetation / повторная проверка опоры стволов; учёт соседей по
   coarse-высотам (P1-3).

**P2 — подключение генерированных текстур**
5. Remap/перепривязка листвы на `cu_organic_leaf_*` (P2-1) + контрольные кадры;
   детектор orphaned-блоков в `assetgen audit`.

**P3 — бэклог**
6. O-1 рентген-дыры (рендер-бисект), O-2 SurfaceYAt (binsearch + кэш RouteAt),
   ~~O-3 фикс теста~~ (закрыт: не воспроизводится), O-4 prefab id-drift, builtin-ранги по паку, repo hygiene.

Порядок 1→2→3→4→5; P0/P1 независимо друг от друга, P2 после P1 (кадры одни и те
же). Старые сохранённые миры не мигрируют автоматически (prune/decay меняют
только новую генерацию и события разрушения — сохранения не ломаются).

## 5. Ход работ (2026-11-02)

**P0-1 выполнен** (ветка `fix/leaf-raycast-targeting`, merge 7eb7c5791):
`BlockRaycastTargetMode { SolidOnly, Pointable }` в `RaycastSolidBlocks`
(`src/World/Raycast/BlockRaycast.h`); Pointable = движение-блокирующие плюс
не-solid cutout/cross (не жидкости). Pointable используют: `ResolveBlockPlacement`
(break_hit — отдельный луч Pointable, позиция установки — прежний SolidOnly-луч,
чтобы установка не «прилипала» к траве — подтверждено эталонным
`block_placement_raycast_test`), `CheckRayIntersection`, `DelObjectByView`.
Существа (LoS атаки), `PickCreatureByView`, окружение — остались на SolidOnly.
Регресс-тест `block_raycast_target_test` (листва/cross/вода в обоих режимах).

**P0-2 выполнен** (ветка `feat/leaf-break-cascade`, merge 9a198c89a):
`BreakUnsupportedVegetationCluster` (`ObjectUtil.cpp`) — после вертикального
каскада DelBlockAt зачищает 26-связный кластер не-solid не-жидких блоков вокруг
сломанной клетки, если рядом (26-связность) нет ни одного movement-блока
(пень/земля/стена держат кластер). Лимит 4096. Регресс-тест
`leaf_break_cascade_test` (5 сценариев). Итог: срубил все брёвна — крона
исчезла; тыкнул в парящий ком генерации — он исчез целиком.

**P1-3 выполнен** (ветка `fix/mudflow-before-vegetation`, merge 1590412ca):
mudflow перенесён с «после пост-терраин стадий» на «после аналитических
караверов, до Vegetation» (`PipelineChunkPopulator::Populate`); деревья

Worldgen-тесты (vegetation ×3, mudflow, smoothness, hills gate, fluid) — OK.
Полнообластные метрики/гейты после переупорядочения не пересчитывались

**P1-1 (prune cross-chunk крон) — отложен после глубокого анализа.** Реализовывалось
три варианта (провенанс-биты в UChunk + prune после ApplyTo; флаг «секция
заселена»; prune-void против повторного заполнения) — все дают остаточную
зависимость от порядка применения чанков: суждение «поддержка» читает
live-мир, содержимое которого к моменту суждения зависит от порядка
(tie-break `incoming < current` равных рангов + удаление + повторное применение
в воздух). Разведка 2026-11-03 (хук `CUBA_DEBUG_PRUNE=1`, flight-sim по свежему
миру, вывод в glog): гипотеза «воркеры видят неверную физику листвы»
**опровергнута** — в worldgen-потоке `tree_leaves`/`mtg_leaves`/`leaves_spruce`
имеют occupancy 0, `BlocksMovement` 0, removable 1, определения пак
`cubatarium_worldgen_cc0` загружены; prune активно удаляет (первые чанки:
pruned=6/10/2). «Парадокс выживающих крон» в сохранениях объясняется
поддержкой: при плотном лесе стволы соседних деревьев дают диагональную опору
большинству листьев (в секции y64–79 мира ProbePrune2026 — 172 стволовых
вокселя против 332 колонок кроны), а латальные края крон честно срезаются.
Остаётся единственный реальный дефект — **колонки крон на швах чанков никогда
не прюнятся**. Пути реализации (по-прежнему на выбор): (а) placement-time
обрезка крон по детерминированному `CoarseSurfaceYAt` соседних колонок
(чистая функция от seed, без cross-chunk состояния) или (б) полноценный
provenance + deferred prune по барьеру «колонка заселена целиком». Текущий
компромисс: парящие кластеры генерации убираются геймплеем (P0-1 + P0-2:
тыкнул — кластер исчез). Диагностический хук оставлен в коде (env-гейт,
3 чанка на процесс).

Тесты после всех стадий: 11/11 целевых тестов OK, ctest 10/10
(зарегистрированные), verify-windows-exe PASS.
